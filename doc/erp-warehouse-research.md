# ERP 仓库管理系统调研与产品结论

> 调研日期：2026-11-08  
> 调研目的：为 Lager 仓储（本项目）确定第一版功能边界、业务流程、数据对象、体验原则和安全性能基线。  
> 说明：本文是二手资料研究与开源项目对照，不替代真实企业的业务调研；所有外部链接均为参考资料。

## 1. 结论摘要

1. **WMS 的核心不是“记账”，而是“让每一次库存变化都有原因、有单据、有责任人、可追溯”。** 因此系统必须同时具备主数据、作业单据、库存余额、库存流水和审计日志五类能力。
2. 中小企业最容易落地的闭环是：**商品/仓库/往来单位 → 入库 → 库存 → 出库 → 调拨 → 盘点 → 报表**。第一版不应一开始就做生产制造、财务总账、复杂批次/序列号、波次拣选，否则参数和操作会把新手淹没。
3. ERPNext 的可借鉴点不是它的页面数量，而是它的**单据状态机**：草稿可改，提交后产生不可变的库存流水，错误通过冲销/调整修正；同时提供库存余额、库存流水、库龄/周转、低库存等报表。
4. 对新手最友好的设计是**“一页一事、下一步明确、危险操作二次确认、提交后只读”**。列表页只保留搜索、状态、仓库三个主要过滤条件；创建单据采用“表头 + 明细行”两段式，并实时显示合计。
5. 安全与性能必须内建在架构中：Cookie 会话、角色权限、登录限流、参数化查询、审计日志、SQLite WAL、索引、分页、原子库存扣减、静态资源压缩与缓存。

## 2. 什么是 ERP 仓库管理

仓库管理系统（WMS）把收货、检验、上架、存储、拣货、复核、包装、发运、退货和补货变成可跟踪的流程。它既记录“有多少库存”，也记录“为什么变、在哪里变、由谁变”。ERP 中的仓储模块则进一步把库存与采购、销售、供应商、客户和财务连接起来。

参考资料中的共识流程：

```text
供应商到货 → 核对单据/采购单 → 数量与质量检验 → 上架/入库
→ 库内存储与盘点 → 接收客户订单 → 拣货 → 复核/包装
→ 发运/出库 → 退货检验 → 良品回库或隔离/报损
```

## 3. 典型功能地图

| 能力域 | 典型功能 | 第一版取舍 |
|---|---|---|
| 主数据 | 商品/SKU、条码、分类、单位、仓库、库位、供应商、客户 | 做商品、仓库、供应商、客户；库位留到后续 |
| 入库 | 采购收货、退货入库、其他入库、质检、上架 | 做“入库单”，支持草稿/确认/取消，确认即入账 |
| 出库 | 销售发货、领料、其他出库、拣货、复核、发运 | 做“出库单”，确认前校验可用库存 |
| 库内 | 调拨、移库、调整、盘点、冻结 | 做调拨、库存调整、全仓盘点 |
| 库存 | 实时余额、流水、可用量、安全库存、周转、库龄 | 做余额、流水、安全库存、库存价值 |
| 报表 | 库存汇总、收发存、低库存、库存流水、周转率 | 做库存汇总、低库存、流水、收发存导出 |
| 系统 | 用户、角色、审计、参数、备份 | 做用户/角色、审计、系统信息、备份说明 |
| 高级 | 批次/效期、序列号、多单位换算、波次、库位、条码枪、API 集成 | 明确列为后续版本，不在第一版堆参数 |

## 4. ERPNext 对照研究

ERPNext 是开源 ERP，Stock 模块提供库存跟踪、商品管理、库存交易、库存对账、报表分析等能力。其 Stock Entry 支持多种目的：Material Issue、Material Receipt、Material Transfer、Manufacturing、Repack、Subcontracting 等；提交后通过库存流水影响余额，错误通常通过取消/修正或库存对账处理。

对本项目的启示：

1. **单据 + 台账双轨**：单据负责业务语义，库存流水负责不可变事实。不要只改余额而不留流水。
2. **用“用途/类型”表达业务**：第一版用入库、出库、调拨、盘点四类单据覆盖 80% 场景，比复制 ERPNext 的全部 Stock Entry 类型更清晰。
3. **提交后不可直接改**：已确认单据锁定，修正通过反向业务或盘点/调整完成，保证审计链完整。
4. **仓库是库存的第一维度**：同一商品在不同仓库的库存必须分开计算；调拨是“源仓出、目标仓入”的原子操作。
5. **报表要能回答管理问题**：总库存价值、低库存、某商品在某仓库的余额、某段时间的收发存，而不是只炫耀图表。
6. **不要照搬复杂表单**：ERPNext 面向实施顾问，字段多；本项目面向第一次接触 ERP 的小团队，默认值、分步填写、解释性文案比字段数量更重要。

## 5. 关键业务规则（本项目采用）

### 5.1 库存

- 库存余额唯一键：`(商品, 仓库)`。
- 库存数量允许 3 位小数，金额允许 2 位小数；数据库使用定点数，禁止用浮点数做金额累计。
- 每次确认业务单据，必须同时写库存余额和库存流水，二者在同一事务内完成。
- 出库/调拨源仓出库前必须校验可用库存；不足则整单失败，不允许部分成功。
- 采用**移动加权平均成本**：入库更新平均成本；出库、调拨转出按当前平均成本记流水；调拨转入继承源仓成本。
- 已确认单据不可编辑。需要使用库存调整或反向单据纠错。
- 盘点以“系统快照数量 vs 实盘数量”生成差异，确认时统一调整。

### 5.2 单据状态机

```text
草稿 DRAFT ──确认──> 已确认 CONFIRMED
   │
   └──取消──> 已取消 CANCELLED

盘点：草稿 DRAFT ──开始盘点──> 盘点中 COUNTING ──确认──> 已完成 COMPLETED
```

- 只有草稿可以编辑、删除。
- 确认动作必须幂等：重复点击不会重复扣减库存。
- 取消只允许草稿；已确认单据通过调整单纠错。

### 5.3 角色

| 角色 | 权限 |
|---|---|
| 管理员 admin | 全部功能、用户管理、审计日志、库存调整 |
| 主管 manager | 业务单据全部操作、库存调整、报表；不可管理用户 |
| 操作员 operator | 查看主数据/库存，创建并确认入库、出库、调拨、盘点 |
| 只读 viewer | 只读查看，不可写 |

第一版采用固定角色 + 后端权限依赖，避免复杂的自定义权限矩阵。

## 6. 仓库 KPI 与管理报表

调研中反复出现的仓储 KPI：

- 库存准确率 = 盘点一致行数 / 盘点总行数
- 库存周转率 = 期间出库成本 / 平均库存价值
- 低库存商品数 = 余额低于安全库存的商品数
- 收货及时率 / 发货及时率
- 订单满足率 / 缺货率
- 库存总价值、呆滞库存（后续版本）

第一版工作台展示：库存 SKU 数、库存总数量、库存总价值、低库存数、本月入库/出库单数、近 7 日出入库趋势、低库存清单、最近单据。报表页提供库存汇总、低库存、流水查询和 CSV 导出。

## 7. 新手友好与 macOS 风格的设计结论

1. **减少首屏认知负担**：侧边栏按“总览 / 基础资料 / 库存作业 / 分析 / 系统”分组；每组不超过 5 项。
2. **一屏一个主任务**：列表页主按钮唯一（如“新建入库单”）；详情页主操作唯一（“确认入库”）。
3. **用人类语言而非数据库语言**：`入库单`、`供应商`、`可用库存`，而不是 `InboundOrder`、`Partner`。
4. **表单分块**：单据头（谁、哪个仓、什么时候）与商品明细分开；必填项少，默认今天、默认草稿。
5. **即时反馈**：保存成功 toast、确认前摘要弹窗、库存不足明确到商品和仓库。
6. **空状态即教程**：没有商品时直接给“先建一个商品”的按钮和一句话解释。
7. **macOS 视觉语言**：系统字体、浅灰背景、白色半透明侧栏、克制的分隔线、10–12px 圆角、柔和阴影、蓝色主操作、少量语义状态色；不使用窗口红黄绿装饰点、厚重渐变和过多装饰。
8. **键盘与可达性**：所有操作可 Tab 到达、焦点环清晰、触控目标 ≥44px、对比度 ≥4.5:1、支持减少动效。
9. **响应式**：桌面优先，1280px 三栏/两栏自适应；小屏侧栏折叠为抽屉，表格允许横向滚动。

## 8. 安全与性能启示

安全：
- 身份认证使用 HttpOnly + SameSite Cookie，避免把长期令牌放进 localStorage。
- 密码使用强哈希（PBKDF2-SHA256），登录失败限流。
- 后端每个写接口做角色校验，前端隐藏按钮只是体验，不是安全边界。
- 所有查询参数化；所有输入做长度/枚举/数值范围校验。
- 审计日志记录登录、主数据变更、单据确认/取消、库存调整、用户管理。
- 响应头增加 CSP、X-Frame-Options、nosniff、Referrer-Policy。
- SQLite 文件不放静态目录，容器以非 root 运行。

性能：
- SQLite 开启 WAL、`synchronous=NORMAL`、`busy_timeout`。
- 为 SKU、单据号、状态、仓库、商品、创建时间建立索引。
- 列表分页，默认 20 条；聚合查询走数据库而非前端。
- 前端路由懒加载、图标按需、静态资源长缓存、API gzip。
- 单据确认使用条件更新/事务，避免并发超卖。

## 9. 第一版范围（已锁定）

**做：** 登录/角色、工作台、商品、仓库、供应商、客户、库存余额/流水/调整、入库单、出库单、调拨单、盘点单、库存报表/低库存/收发存 CSV、用户管理、审计日志、Docker Compose、Windows 一键启动、种子演示数据、完整中文文档。

**不做（后续版本）：** 采购订单/销售订单全流程、财务凭证、生产制造、批次/效期、序列号、多单位换算、库位/货架、波次拣选、条码枪原生客户端、多租户、第三方电商/物流 API。保留清晰扩展点，不在第一版引入参数负担。
