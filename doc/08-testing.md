# Lager 仓储 · 测试计划

版本：1.1  
日期：2026-11-09  
原则：**所有功能开发完成后统一进入测试阶段**；测试前不写测试代码、不边写边测。  
关联：[PRD](01-product-requirements.md)、[API](04-api-spec.md)、[安全](06-security.md)、[性能](07-performance.md)

## 1. 测试目标

1. 验证 PRD 中 P0 需求全部可用、可追溯。
2. 验证库存一致性、单据状态机、权限边界在正常与异常路径下正确。
3. 验证前后端契约一致，关键用户旅程无阻断。
4. 验证安全基线（认证、越权、注入、CSRF、响应头）。
5. 验证性能目标与部署方式（Docker Compose / Windows bat）。
6. 产出可复现的测试报告与缺陷清单；未通过项不得宣称完成。

## 2. 测试范围

**包含**

- 登录/登出/改密、RBAC。
- 工作台、商品、仓库、供应商、客户。
- 库存余额/流水（只读）；商品页清空库存。
- 入库、出库、调拨、盘点全流程。
- 报表与 CSV 导出。
- 用户管理、审计日志。
- AI 设置、DeepSeek/Ollama 适配、截图（含剪贴板粘贴）/链接/文字分析、预览编辑、导入与重复令牌。
- 所有列表的当前页全选/复制；可删除列表的批量清除（二次确认、逐条结果、失败保留）；Intro.js 桌面与移动端新手指引。
- 响应式布局、空/错/加载态、键盘操作。
- Docker Compose 与 Windows 一键启动。

**不包含（v1.1）**

- 采购/销售订单、财务凭证、批次/效期、序列号、库位、多单位、多租户。
- 浏览器兼容 IE；支持最新 Chrome/Edge/Firefox/Safari。
- 大规模压测（>20 并发）；仅基准测试。
- 渗透测试全项；仅安全清单。

## 4. 测试环境

| 环境 | 用途 | 数据库 |
|---|---|---|
| 单元/集成 | pytest，临时目录 | 每个测试独立 SQLite 文件，建表后种子 |

- Python 3.11（与 Docker 一致；本机 3.9 仅开发兼容需注意类型语法）。
- Node 20+，pnpm。
- 浏览器：Chrome 最新版；Firefox/Safari 抽查。
- 屏幕：1440×900、1024×768、390×844。

> 兼容性说明：本机 Python 3.9.1 不支持 `X | None` 的运行时求值（除非 `from __future__ import annotations`）。后端代码统一使用 `Optional[...]` 或启用 future annotations，确保 3.9 可运行、Docker 3.11 亦可。

## 5. 测试数据

- 种子：管理员、主管、仓管、只读各 1；2 仓库；10 商品（含低库存）；3 供应商/客户。
- 边界数据：0 库存、超大数量（999999.9999）、4 位小数、长名称（120 字）、特殊字符 `<>&"'`、中文/英文/数字 SKU。
- 隔离：集成测试使用临时数据库；E2E 使用独立验收库，测试后重置。
- 禁止在真实数据上跑破坏性用例。

## 9. 安全测试

执行 [06-security.md](06-security.md) 第 13 节清单，另加：

- 会话固定：登录前后 Cookie 值变化。
- JWT 篡改 `role`/`sub`/`ver` → 401。
- 旧令牌在改密后 → 401。
- CSRF：跨站表单 POST 不带 Cookie；SameSite 生效。
- XSS：商品名/备注/审计详情注入脚本不执行。
- SQL 注入：搜索、排序、筛选参数。
- 越权：OPERATOR 调用调整、用户管理、审计；VIEWER 全部写。
- 暴力破解：限流与 429 文案。
- 响应头：CSP、X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy。
- 容器：非 root、只读根、cap_drop、无密钥入库。
- 错误信息：无堆栈/SQL/路径。
- AI：Key 不回显/不明文落库；token 一次性；SSRF；图片伪造；提示词注入；6 MB 限制。
- 引导：Intro.js 不遮挡关键按钮；移动端抽屉可关闭；不因引导阻断业务。
