## 1. 产品定位

Lager 仓储是一套面向中小企业仓库团队的单体部署 ERP 仓储系统。它用**少量必填字段、清晰的状态流转、可追溯的库存流水**覆盖收货、存储、发货、调拨、盘点和分析，让第一次使用 ERP 的仓管员在一个工作日内上手。

**一句话价值**：让每一次库存变化都有单据、有原因、有责任人。

**目标用户**

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 仓库主管 张敏 | 每天核对库存、处理异常、看报表 | 库存准、可追溯、快速发现低库存 |
| 仓管员 李伟 | 收货、发货、调拨、盘点 | 操作少、看得懂、不会误操作 |
| 老板/运营 王芳 | 看库存价值和周转 | 一屏看懂、能导出 |
| 系统管理员 | 开通账号、排查问题 | 权限可控、审计完整、部署简单 |

## 2. 设计原则

1. **单据驱动**：库存不能“直接改数字”，必须通过入库、出库、调拨、盘点或调整产生流水。
2. **提交即入账、确认即锁定**：减少“保存了但不知道有没有生效”的歧义。
3. **默认值优先**：仓库、日期、单位、状态给出合理默认值，减少输入。
4. **危险操作可逆但不可隐**：确认前二次确认；确认后不可编辑，通过调整/反向业务修正并留审计。
5. **模块独立**：认证、主数据、库存、入库、出库、调拨、盘点、报表、系统管理各自拥有模型、服务、路由，改动一个模块不要求改其他模块内部实现。
6. **前端只做体验，不做权限边界**：所有权限在后端再次校验。
7. **中文优先、术语一致**：同一概念全站只用一个词。

## 3. 范围

### 3.1 本期范围（v1.0）

- 账号登录、退出、当前用户、修改密码、角色权限
- 工作台：库存 KPI、7 日趋势、低库存、最近单据、快捷入口
- 基础资料：商品、仓库、供应商、客户（增删改查、搜索、分页、启停）
- 库存：按商品/仓库只读查询余额与流水；商品页负责清空库存
- 入库单：草稿、编辑、确认入库、取消、详情
- 出库单：草稿、编辑、确认出库（库存校验）、取消、详情
- 调拨单：草稿、编辑、确认调拨（同仓校验、库存校验）、取消、详情
- 盘点单：创建全仓快照、录入实盘数、确认差异调整、取消
- 报表：库存汇总、低库存、库存流水、收发存汇总、CSV 导出
- 系统：用户管理、审计日志、系统健康检查
- 部署：Docker Compose（Ubuntu 一键）、Windows `start.bat` 一键、本地开发说明
- 种子数据：首次启动创建管理员；可选演示数据

### 3.2 v1.1 增量范围

- 所有业务列表的当前页全选、逐行选择、复制选中；可删除档案/草稿单据支持批量“清除数据”（二次确认、失败保留）。库存、流水、用户、审计、报表只读，不提供删除。
- Intro.js 新手指引，桌面/移动端可用并可重复打开。
- DeepSeek（默认）/Ollama 双提供商设置；API Key 加密、只写不回显。
- 可编辑的默认提示词（类 Skill 结构，含 JSON Schema 与硬约束）。
- 购买截图、商品链接、文字三种来源的 AI 识别；预览可编辑；确认后入库。
- 移动端 AI 卡片布局；移动端非模态引导抽屉。
- 文档、测试、部署说明同步到 1.1.0。

### 3.3 明确不做（v1.0 / v1.1）

采购订单、销售订单、财务总账、发票、生产/BOM、批次/效期、序列号、库位/货架、多单位换算、波次拣选、条码枪客户端、多租户、审批流、消息中心、第三方 API。后续版本见 [路线图](10-roadmap.md)。

## 6. 关键用户旅程

### 6.1 第一次使用（空数据）

1. 打开系统 → 登录页显示演示账号提示（仅演示模式）。
2. 登录后工作台显示“开始使用”三步：建仓库 → 建商品 → 建第一张入库单。
3. 每步完成后自动打勾；全部完成后显示库存 KPI。

### 6.2 收货入库

1. 侧边栏“入库管理” → “新建入库单”。
2. 选择供应商、仓库（默认主仓），点击“添加商品”，搜索 SKU，输入数量和成本。
3. 右侧/底部合计实时更新；点“保存草稿”。
4. 详情页点“确认入库” → 弹窗显示仓库、商品行数、总数量、总金额。
5. 确认成功 → 状态变为“已入库”，toast 提示；库存余额和流水立即可查。

### 6.3 发货出库

1. 新建出库单，选客户、仓库，添加商品和数量。
2. 保存草稿 → 确认出库。
3. 若库存不足，弹窗/页面提示“商品 X 在仓库 Y 可用 3，申请 5”，单据保持草稿。
4. 成功后库存扣减，流水记录成本。

### 6.4 盘点

1. 新建盘点单，选择仓库 → 系统生成快照。
2. 点“开始盘点”，逐行录入实盘数量；差异列实时变红/绿。
3. 点“完成盘点” → 弹窗汇总差异行数与差异金额；确认后调整库存并锁定。

### 6.5 AI 智能入库（v1.1）

1. 管理员在“系统设置”选择 DeepSeek，填写 API Key 并测试连接；或选择本机 Ollama。
2. 仓管员打开“AI 助手”，上传购买截图或粘贴商品链接。
3. AI 返回预览：商品、数量、单价、供应商、warning；匹配商品显示绿点，新建商品显示橙点。
4. 用户修改数量/单价、选择仓库和供应商，点“确认并入库”。
5. 系统重新校验并创建入库单；开启自动确认时库存立即增加；成功后跳转单据详情。
6. 若预览超过 30 分钟或重复导入，系统提示重新识别，不重复写库存。

## 7. 非功能需求

### 7.1 安全

- 密码 PBKDF2-SHA256 强哈希，绝不明文存储或返回。
- 会话 Cookie：HttpOnly、SameSite=Lax、生产环境 Secure、8 小时过期。
- 登录失败限流：同一 IP+用户名 15 分钟内 5 次失败后锁定 15 分钟。
- 所有写操作后端角色校验；所有 SQL 参数化。
- 审计日志不可通过 API 修改/删除。
- 安全响应头：CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy、Permissions-Policy。
- 生产环境必须设置 `SECRET_KEY`；默认值仅用于本地演示，启动时在非 dev 环境给出警告。
- 容器非 root、只读根文件系统（数据卷除外）、`no-new-privileges`。

### 7.2 性能

- 本地/单机 1000 商品、10 万条流水规模下：列表接口 P95 < 300ms，工作台 < 500ms（普通笔记本）。
- 列表默认 20 条，最大 100 条；禁止无分页全量返回。
- 首屏 JS gzip 后 < 350KB（路由懒加载）。
- 数据库 WAL 模式；为高频过滤字段建索引。
- 前端搜索 300ms 防抖；路由切换有加载骨架。

### 7.3 可用性

- Chrome/Edge/Safari 最近两个大版本；桌面 1280px 起最佳，支持 375px 窄屏。
- 界面中文；金额 ¥；日期 `YYYY-MM-DD`；数量最多 4 位小数。
- 关键操作有成功/失败反馈；错误文案可执行（告诉用户下一步）。
- 支持 `prefers-reduced-motion`。
- 键盘可完成登录、导航、表单、弹窗关闭。

### 7.4 可维护性

- 后端按业务模块分包，模块内 router/schemas/service/models 高内聚。
- 模块之间只通过显式 service 函数或共享 `inventory` 服务交互，不跨模块直接改表。
- 前端按 feature 分包，通用 UI 组件与业务组件分离。
- 统一响应错误结构与 API 客户端；无散落 fetch。
- 所有配置来自环境变量，代码中无生产密钥。
- 文档与代码同仓库，API 变更先改文档。

### 7.5 数据与备份

- SQLite 单文件数据库默认位于 `data/lager.db`。
- Docker 使用命名卷 `lager_data`。
- 文档提供在线备份（`sqlite3 .backup`）与恢复步骤；建议每日备份。
- 不提供自动备份调度（避免在应用内引入复杂任务系统），由宿主机 cron 完成。

## 8. 验收标准（摘要）

1. 全新环境启动后可用 `admin` 初始账号登录，强制/提示修改初始密码（提示即可）。
2. 可以创建仓库、商品、供应商、客户，并出现在对应列表。
3. 入库单从草稿到确认后，库存余额增加、平均成本正确、流水生成、单据只读。
4. 出库单库存不足时整单失败且库存不变；足够时扣减且流水成本正确。
5. 调拨后源仓减少、目标仓增加，总库存不变，生成两条流水。
6. 盘点录入差异并完成后，余额与流水调整正确，状态锁定。
7. 库存调整必须填原因，生成 ADJUSTMENT 流水。
8. 低库存报表与工作台数量一致；CSV 可用 Excel 打开。
9. 非管理员无法访问用户管理与审计日志接口（403）。
10. 重复确认同一单据返回 409，库存不重复变化。
11. Docker Compose 一条命令启动；Windows `start.bat` 可启动并打开浏览器。
12. 所有页面在 1280×800 与 390×844 下无横向溢出（表格自身滚动除外），无控制台错误。

## 9. 成功指标（上线后）

- 新用户 10 分钟内完成第一张入库单。
- 库存调整率 < 2%（盘点差异行数/总行数）。
- 单据重复确认导致的库存差错 = 0。
- 页面核心任务完成率 > 95%（可用性测试）。
- 低库存商品在 24 小时内被看到并处理的比例 > 80%。

## 10. 术语表

| 术语 | 含义 |
|---|---|
| SKU | 商品唯一编码 |
| 可用库存 | 当前仓库中可出库的数量（本期不做预留，等于账面数量） |
| 移动加权平均成本 | 每次入库后按“原库存金额+入库金额”除以新数量得到的单位成本 |
| 库存流水 | 不可变的库存变动记录，包含变动前后数量与关联单据 |
| 草稿 | 可编辑、未影响库存的单据 |
| 确认 | 单据生效并写入库存流水，之后不可编辑 |
| 盘点快照 | 创建盘点单时记录的系统账面数量 |
